# Windows推論のメモリ設定とランタイム切替

設定画面の「変換と候補」→「ZeroCon AI」でバックエンドと「GPUに載せる層数」を選択する。

- 全層（既定、JSONでは99）: 従来どおりモデル全体を可能な範囲でGPUへ載せる。
- 最大16・8・4層: 指定した層までをGPUへ載せ、残りの重みはRAMに置いてCPUで処理する。4層はRAMを優先した選択肢。
- 0層（CPUで推論）: モデルの重みをRAMに置き、CPUで推論する。CPU負荷が増え、推論が遅くなる場合がある。Vulkan/CUDAランタイムは使用し続けるため、作業領域などにVRAMが使われる場合があり、VRAM使用量がゼロになる設定ではない。
- CPUバックエンド: 保存した層数にかかわらず0層として実行する。GPUへ戻すと保存した層数を使用する。

GPUで処理する部分にはVRAMが必要であり、「すべてRAMに置き、すべてGPUで同じ速度で処理する」設定ではない。層数を減らすとIMEの推論が遅くなる場合がある。他のローカルLLMへの影響はモデル・同時実行・ドライバーにも依存するため、節約量や速度は実測で判断する。llama.cppの層数オフロードの説明は[公式ドキュメント](https://github.com/ggml-org/llama.cpp/blob/master/docs/development/token_generation_performance_tips.md)を参照。

保存先は `%APPDATA%/Azookey/settings.json` の `zenzai.gpu_layers`（0〜99）。旧設定でキーがなければ99とする。漢字変換のSwiftランタイム、内蔵タイポ補正、ZeroCon先読み、設定画面のモデルベンチマークで同じ値を使う。外部アプリが起動した推論サーバーの設定は変更しない。配布初期設定は既存の個人設定を上書きしない。

バックエンドを変更すると、既に読み込まれたllama DLLを入れ替えるため、IMEの変換サーバーを自動で再起動する。層数変更もモデルの再ロードのため同様に再起動する。設定保存中のクロスプロセスロックはサーバー再起動を待つ前に解放し、再起動後にIPC接続を作り直す。補正・先読みはlauncherが所有する子プロセスだけを監視し、設定差分を約2秒ごとに検出して停止・起動する。

変更前に入力中の文字を確定する。切替中は一時的に変換やアシストが使えない場合がある。反映に失敗した場合は保存済みと未適用を区別して表示し、「IMEサーバーを再起動して再試行」からやり直せる。ランタイム設定の切替にWindowsの再起動は不要。

インストーラーでTSF DLLなどを更新する際のWindows再起動要求は別の仕組み。入力アプリに読み込まれた旧DLLの扱いまで、ランタイム設定の切替で解決するものではない。
