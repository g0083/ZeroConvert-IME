# Androidのカーソル通知による意図しない確定の修正（2.0.10-dev）

2026-10-26、ライブ変換ONの未確定入力中に矢印を押すと全文がひらがなになって
確定される報告に対応した。

## 原因と修正

矢印キーでは読みのカーソルを動かし、InputConnectionに未確定文字とカーソルを
設定してからカーソル前の候補を更新する。ComposingEditorStateは、その操作に
対応する選択通知を外部操作と区別している。

従来はカーソル位置と変換範囲の両端の完全一致が必要だった。カーソル位置は
IMEが指定した値でも、通知の変換範囲の終端が古い場合や、範囲が省略された場合は
自分の操作と認識できず、onUpdateSelectionがclearInputとfinishComposingTextを
呼んでいた。読みの書き戻しのタイミングでこの通知が来ると、全文がひらがなのまま
確定され、後から来る変換結果も無効になる。

Android側の所有判定を、要求したカーソル位置と、通知されている場合の変換範囲の
開始位置で照合する。範囲終端の遅れと両端-1の省略を許容する。
違うカーソル位置、開始位置の不一致、不正な片側だけの範囲、省略ではない不正範囲、
範囲選択は自分の操作とは扱わない。通知履歴の上限16件とclear時の破棄も維持する。

ライブ変換設定、原打鍵・読み、カーソル前候補取得、部分確定、実際の外部移動を
処理するサービスの経路は変更していない。共有エンジンとモデルにも変更はない。

候補が残ること、続く左右移動・部分確定・残りの確定・文字数表示が動くことを確認した。

- 基本24項目：成功、失敗0。英字のEnterとモード切替の保持も含む。
- 未完ローマ字10項目：ライブ変換ON/OFFとも成功、失敗0。
- クリップボードUI7項目：成功、失敗0。
- 端末内APKの版とSHA-256を固定保存したAPKと照合。設定画面の起動も確認。
- 試験時の設定は元へ復元し、学習書込みを抑止。

テストAPKのSHA-256は `659c2bc4eeee1893cc55841a251019ed7b7073c6efc6781998c4a7534bd8e7f0`。
