# Android移植 第10段階: 形態素の頻度学習

2026-10-24。[第9段階](android-windows-port-stage9.md) の確定成功後の学習経路に、通常辞書の形態素履歴を接続した。既存の読み→選択表記500件は保持し、新しい履歴を `files/conversion-learning-v1.bin` に保存する。

## Windowsとの対応と接続範囲

参照したのはWindowsのSwift依存 `DictionaryManagement/LearningMemory.swift` の `LearningManager.update`、`TemporalLearningMemoryTrie.memorize`、`LongTermLearningMemory.valueForData/merge` と、`DicdataStore.swift` の品詞分類・学習対象判定。

- 単語は読み・表記・左/右CIDで同一性を判定し、MIDが異なるだけなら別件にしない。助詞・助動詞・接頭辞・接尾名詞・記号等の単語学習除外も同じCID範囲を使う。
- 確定した形態素から単語、文節bigram、確定全体を更新する。文節境界、意味IDを引き継ぐ条件、bigramにfirst.rcidを使う既存Swiftの挙動も合わせた。部分確定では直前の最後の形態素を文脈に加え、その単語自体は再学習しない。
- 回数は255で飽和。評価値は `-1 - 4/読み長 - 3*(1-count/255)^3`。UTC日数を基準に、32日を超えるごとに回数を半減し、128日未使用または回数0で除外する。時計が過去へ戻った履歴は回数1・当日に戻す。
- `charID.chid` にない読みはその履歴項目を保存しない。未知文字を含む文でも、他の有効な単語は学習する。
- 候補の読み・表記を完全に覆う形態素だけを確定前にコピーする。学習除外候補、適用済み補正、機密欄は除外する。読み取り専用では利用のみ、無効では利用も記録もしない。
- 通常の確定と部分確定を上限128件の順序付きIO処理から保存する。履歴消去時に世代を進め、消去前の保存待ちイベントによる復活を防ぐ。
- 学習語は品詞ID・意味ID・評価値を保持してJNIに渡し、nativeの文中ラティスへ入れる。読みの部分文字列インデックスで対象を絞り、毎打鍵で全履歴を走査しない。キャッシュキーには学習項目と回数・日付も含める。

保存形式はAndroid用のCRC付きバイナリとAtomicFile。全件の検査が通るまでライブ履歴へ反映しない。破損時は元ファイルを残して新しい形態素履歴の利用・保存を停止し、利用者の既存の履歴消去操作でのみ解除する。既存の選択表記履歴は別に保持する。設定画面の初期読込・登録語追加/削除・履歴消去もIOへ移し、保存中のロックやファイル処理でUIを待たせない。

Androidの処理上限は65536項目、同じ読み255項目、最大入力512文字、1形態素20文字。履歴超過時は短い読みを優先する。保存データの上限は64MiB、大きい履歴の辞書応答はキャッシュへ残さない。SwiftのLOUDSファイル形式・シャード単位の上限超過・同長の保持順までバイナリ互換にするものではない。
