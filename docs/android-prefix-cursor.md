# Androidカーソル左側の変換

2026-10-26。矢印で未確定文字列の途中へ移動し、カーソル左側を変換したいとき候補が表示されない問題を修正。

## Androidホストの変更

- 内部の読みカーソルだけでなく、入力先の実カーソルも左部分と右部分の境界に置く。
  変換表示の更新で未確定範囲の末尾へ戻さない。
- IME自身が要求した範囲内のカーソル通知を識別し、未確定入力を終了する外部選択と区別する。
  遅れて届いた自身の通知でも現在のカーソル状態を書き換えない。履歴は16件に制限する。
- 確定済みの文脈は、カーソル左側にある表示部分だけを除いて取得する。
  右側の読みまでカーソル前にある前提で検証し、変換応答を破棄する問題を防ぐ。
- 矢印移動時に古い候補を消し、左部分の候補を改めて要求する。物理/リモート入力の単独左右キーも同じ経路へ渡す。
- 左部分の確定では、候補が消費した読みだけを取り除き、残りを未確定入力として保持する。
  左部分の最後の文字を削除しても右側を消さない。矢印・削除はサロゲートペアを分断しない。

`ComposingEditorState.kt` が実表示・表示内カーソル・自身の選択通知の履歴を持ち、
読みや候補IDから分離する。通常の末尾入力にはエディタの追加取得・選択変更・バッチを増やさない。
途中への位置決め時だけ、範囲を指定した抽出要求から絶対位置を求める。
抽出部分の先頭位置を考慮する計算は [AndroidのExtractedText仕様](https://developer.android.com/reference/android/view/inputmethod/ExtractedText) に従う。
取得できない入力先では、直近に確認済みの未確定範囲の開始位置を使う。
どちらも不明、または選択変更が拒否された場合は候補を適用しない。

製品変更は `ZeroConvertInputMethodService.kt`、`ComposingEditorState.kt`、`EditorContext.kt`。
テストは `ComposingEditorStateTest.kt` と `EditorContextTest.kt`。
`:rebuilt` の版を2.0.3-dev / versionCode 5に更新し、この2クラスもテスト対象に含めた。
共通Swift/Rustの変換順位・モデルは変更していない。
