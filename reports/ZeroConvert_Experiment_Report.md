# ZeroConvert-IME 包括的実験レポート
**〜汎用軽量LLMの破綻から特化型モデル（Zenzai）の量子化・実証までの全記録〜**

---

## 1. エグゼクティブサマリー

本プロジェクトでは、入力キー数を極小化し自動確定を行う「ZeroConvert-IME」の実現に向け、軽量LLM（1B〜1.5B級）および各種モデルアーキテクチャの日本語かな漢字変換性能・遅延・リソース効率を徹底検証しました。

その結果、以下の事実が実験的に証明されました：

1. **当初の「100点満点」はバグによる偽装だった**:
   プロンプトで候補から選択させる方式（案C）は、正解位置を固定したテストセットとThinkingパース失敗時のフォールバック（第1候補選択）が噛み合って偶然100点になっていただけだった。正解位置をシャッフルした厳格テスト（全230問）では、全1.2Bモデルの正解率が **25%前後（4択の当てずっぽう確率）** に急落し、汎用LLMでのプロンプト選択アプローチは完全に破綻した。
2. **本物Zenzai（zenz-v3）の圧倒的性能の実証**:
   従来「43点」と誤認されていたZenzaiは、実は別モデル（rinna-gpt2）の誤評価だった。azooKey同梱の本物モデル（72MB）を直接検証した結果、**総合正解率 83.5%（同音異義語 89.0%）、遅延 24ms** という圧倒的な実用性能を発揮した。
3. **zenzの再量子化に成功（50MB未満・81.7%維持）**:
   K-quants再量子化により、**Q3_K_M（49.4 MB）** で **正解率 81.7%（元モデルからわずか-1.8%低下）**、遅延 **26.5ms** を達成。ローカル常駐IMEとして理想的なサイズ・速度・精度の両立を実現した。
4. **最新版 zenz-v3.2（small / xsmall）の検証とimatrix量子化の劇的成果**:
   - **`zenz-v3.2-small (IQ4_XS)`（52.6 MB）**: imatrix適用により、元モデル（Q5_K_M: 70.4MB）やQ4_K_Mを上回り、**同音異義語正解率 92.0%（92/100問）、総合正解率 82.2% という全実験中の新チャンピオン記録** を樹立。Q3_K_Mと同等サイズ（52.6MB）で最高精度を達成。
   - **`zenz-v3.2-xsmall (IQ3_XXS)`（12.6 MB）**: 通常量子化では破綻（19.1%）した12MB台で、imatrixにより **同音異義語 77.0% / 総合 72.6%** を維持。
   - **ライセンス革命**: v3の `CC BY-SA 4.0`（同一ライセンス継承縛り）から **`Apache-2.0` に緩和**され、商用・OSSプロダクトへの組み込み自由度が劇的に向上。

## 2. 実験の経緯と各アプローチの検証

### フェーズ 1: 汎用軽量LLM × プロンプト選択方式（案C）の検証とカラクリ解明

#### (1) 当初の幻想（100点満点）
- 対象モデル：`LFM-2.5-1.2B-Thinking-Distill`、`GLM-4.7-Distill-LFM-2.5-1.2B` 等（IQ1_S / IQ2_XXS / Q2_K / Q4_K_M）。
- 手法：文脈・読み・候補一覧を与え、何番が最適かをプロンプトで回答させる（案C）。
- 初回テスト結果：元の46問テストセットで全問正解（100%）。

#### (2) 厳格テストセット（全230問シャッフル版）による破綻の証明
- テストセット：`kana_kanji_llm_testset_5x.jsonl`（全230問。正解位置をランダムにシャッフル）。
- **測定結果**:
  - `LFM-2.5-1.2B-Thinking (Q4_K_M)`: **26.1%** (60/230)
  - `LFM-2.5-1.2B-Thinking (IQ2_XXS)`: **25.2%** (58/230)
  - `LFM-2.5-1.2B-Thinking (IQ1_S)`: **24.8%** (57/230)
  - `GLM-4.7-Distill-1.2B (IQ1_S)`: **23.5%** (54/230)
  - `JP-2026-1.2B (最新日本語特化モデル)`: **23.5%** (54/230)
- **カラクリ（バグ）の全貌**:
  - 元の46問データは全問 `candidates[0]` が正解だった。
  - Thinkingモデルが `<think>` タグを出力して番号の正規表現抽出に失敗した際、フォールバック（`m else 0`）が作動し、無条件に第1候補を選んでいた。
  - 正解位置を分散させると、**4択の確率期待値である 25%** に見事に収束。汎用1.2Bモデルは指示を理解して候補を選んでいたのではなく、単に当てずっぽう＋バグで100点に見えていただけだった。

### フェーズ 2: 新アプローチの模索と検証

汎用LLMへのプロンプト入力（案C）を放棄し、2つの新アプローチを比較検証。

#### アプローチ①: かな漢字直接変換 特化型言語モデル（Zenzai / zenz-v3）
- **過去の誤解の解明**: 過去のレポートにあった「Zenzai 43点」は、2021年の汎用モデル `rinna/japanese-gpt2-small` であり、本物のZenzaiではなかった。
- **本物モデルの特定**:
  - azooKey-windows 環境から `zenz.gguf`（GPT-2 12層 / 768dim、ファイルサイズ 72.8MB）を取得。
  - 特殊トークン `\uEE02{左文脈}\uEE00{入力カタカナ}\uEE01` による直接生成方式。
- **全230問ベンチマーク結果**:
  - **総合正解率: 83.5% (192 / 230問 完全一致正解)**
  - **文脈依存・同音異義語: 89.0% (89 / 100問 正解)**
  - **平均推論遅延: 28.3 ms (RTX 4070)**
  - プロンプトを一切解釈させず、純粋な言語確率モデリングのみを行うため、ハルシネーションが物理的にゼロ。

#### アプローチ②: 双方向BERT による Masked PLL（Pseudo-Log-Likelihood）
- **モデル**: 東北大日本語BERT（`cl-tohoku/bert-base-japanese-v3`, 111Mパラメータ）。
- **手法**: 文脈文中の対象単語を `[MASK]` に置き換え、候補単語が入る対数尤度を双方向から計算して最大スコアの候補を選択。
- **同音異義語ベンチマーク結果**:
  - **正解率: 73.0% (73 / 100問 正解)**
  - 汎用LLM（25%）を大きく上回るものの、かな漢字変換特化のZenzai（89.0%）には及ばない。

## 4. ZeroConvert-IME 最終推奨アーキテクチャ

以上の全実験結果を踏まえ、ZeroConvert-IME の実用構成を以下のように決定・推奨します：

1. **デスクトップ・標準PC向け（★新・最高推奨モデル）**:
   - **採用モデル**: **`zenz-v3.2-small (IQ4_XS)` (52.6 MB)**
   - **採用理由**: 文脈同音異義語正解率 **92.0%**（過去最高記録）、総合正解率 **82.2%**、遅延 **27.9ms**。Q3_K_Mと同等サイズ（52.6MB）でありながら、元モデル（Q5_K_M: 70.4MB）の精度をも凌駕。Apache-2.0 ライセンス。

2. **モバイル・超省リソース常駐向け（サイズ・速度最優先）**:
   - **採用モデル**: **`zenz-v3.2-xsmall (Q3_K_M)` (15.3 MB)**
   - **採用理由**: わずか **15.3 MB / メモリ約60MB**、遅延 **20.5ms** という異次元の軽さでありながら、同音異義語正解率 **85.0%** を維持。バックグラウンド常駐IMEとして圧倒的な省電力性を実現。
   - ※さらに極小（12MB台）を求める場合は **`zenz-v3.2-xsmall (IQ3_XXS)` (12.6 MB / 同音異義語 77.0%)** が選択可能。

3. **アーキテクチャの結論**:
   - 汎用LLM（1B級）のプロンプト選択方式（案C）は完全破棄。
   - Unicode制御トークンによる **zenz 直接かな漢字変換ストリーミング生成** へ一本化。
