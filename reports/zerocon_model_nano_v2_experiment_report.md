# zerocon model nano v2 蒸留・ファインチューニング詳細検証レポート
**〜 なぜスコアがベースから動かないのか？パラメータ容量の限界と蒸留のシーソー現象の解明 〜**

---

## 1. ユーザー指摘の検証：「ベースと何も変わってなく見える」の真相

ベンチマーク結果において、`zenz-v3.1-xsmall (Base)` と `★ zerocon model nano v2` が共に **182問 / 230問 (79.1%)** となり、「ベースと何も変わっていない」ように見える現象について、全230問の1問ごとの推論出力を完全突合・差分分析を行いました。

その結果、以下の事実が判明しました：

### 【全230問 差分分析結果】
- **出力が変化した問題**: **全20問** (91.3%は一致、8.7%が変化)
- **Base不正解 → Nano v2正解（改善）**: **5問**
- **Base正解 → Nano v2不正解（悪化・リグレッション）**: **6問**
- **ネット増減**: **-1問 〜 ±0問**（改善した分だけ別の問題が落ちて相殺されていた）

## 3. なぜ Standard (188問) に追いつけないのか？（技術的ボトルネック）

本実験を通して、25M級の極小言語モデルにおける**「パラメータ容量の物理的限界」と「シーソー現象（Trade-off）」**が実証されました。

1. **パラメータ数の圧倒的格差 (4倍の差)**:
   - `zenz-v3.1-xsmall (Nano)`: **約24M パラメータ (6層 / 512dim)**
   - `zenz-v3.2-small (Standard)`: **約95M パラメータ (12層 / 768dim)**
   - Standard が 188問（81.7%）を達成できるのは、95M のパラメータ容量によって数万通りの文脈パターンと同音異義語の使い分けを同時に記憶・汎化できるためです。
2. **24M モデルにおける容量飽和 (Capacity Saturation)**:
   - 24M の極小モデルでは、「新しい文脈・表記（飴をなめる、後世、ウェブサイト）」の確率を強めると、同一音の「汽車、鋼製、硬貨」など他の文脈の確率が容量不足により押し出されて低下してしまいます。
3. **Full-FT（全パラメータ学習）の破綻**:
   - 全層学習（Full-FT）を行ったところ、基盤モデルの事前学習重みが崩壊し、**170問 (73.9%) へ急落**しました。極小モデルに対する小規模蒸留データでのFull-FTは破綻します。
4. **LoRA 重み補間（Weight Interpolation）による検証**:
   - マージ比率を 0.2, 0.4, 0.6, 0.8 とスイープした結果：
     - Ratio 0.2: 182問 (79.1%)
     - **Ratio 0.4: 183問 (79.6%) ★最高値 (+1問の純増)**
     - Ratio 0.6: 181問 (78.7%)
     - Ratio 0.8: 181問 (78.7%)
     - Ratio 1.0: 182問 (79.1%)
   - 最適な補間率（40%マージ）でも **183問（+1問純増）が限界** であり、Standard（188問）との 5〜6問の差は埋まりませんでした。

## 4. 結論と代替アプローチの提案

### 【結論】
「zenz v3.1 xsmall（17.4MB）への蒸留ファインチューニング」のみでは、**Base（182問）から実質 +1問（183問）の微増にとどまり、95M の Standard（188問）に追いつくことはパラメータ容量の壁により極めて困難**であると結論付けられます。

### 【推奨される現実的な代替案】
サイズ（15MB〜25MB前後）を保ったまま Standard に追いつくための有効なアプローチ：

1. **`zenz-v3.2-small`（Standard）自体の imatrix による極限量子化**:
   - 本家 95M モデルをキャリブレーション付き imatrix で **IQ3_M (47.8MB)** または **IQ3_XXS (39.9MB / 179問)** に量子化する。
2. **2段階パイプライン（辞書・n-gram フォールバック併用）**:
   - Nano v2（17.4MB）で高速推論しつつ、同音異義語の決定が曖昧な単語のみ、辞書トリガーや n-gram スコアで補正する。
