3. 補正・先読みパイプライン

変換本線と補助生成を分離し、世代・文脈・設定の一致のみ反映。

タイポ補正経路

  1. AppendText/ReplaceComposition はモデルを待たず応答
  2. クライアントが入力・候補・COM context/composition・文脈・設定・世代をスナップショット
  3. 60ms入力停止後に GetAssistCandidates を別タスクで呼び出し
  4. 専用ワーカーで補正と先読みを独立生成（各1件）
  5. 25msタイマーで結果受信、世代不一致は破棄
  6. 補正は元候補を保持して追加（候補ID維持）
  7. 適用時は direct入力として絶対置換、原文ledgerを保存

先読み経路（ZeroCon）

  1. 通常変換応答後に 60ms停止で補正(kind=1)と先読み(kind=2)を別RPC
  2. 先読みは補正の終了を待たない（並列）
  3. ZeroCon: EE02 + 左文脈 + EE00 + カタカナ読み → 続き生成（24トークン）
  4. 短い句境界まで取り出し、EE02 + 左文脈 + EE00 + 延長読み + EE01 → 表記変換
  5. 現在の表記で始まらなければ破棄
  6. 生成上限断片・制御文字・記号のみ・繰り返し・原表記変更を除外
  7. Tabで追加部分＋全文を確定

妥当性の順序値（relevance）

候補種別値説明
一意な近接キー復元（自動反映根拠あり）100完全な辞書語へ一意復元

同値時は先読みを選択。モデル確率を正解率として扱わない。

4. 非破壊・安全性の設計

誤操作を防ぐため、自動確定と取消を分離。

操作仕様

  • Tabで補正しても確定しない。続けて入力可能
  • 先読みのTabは従来どおり採用・確定
  • 補正適用直後のEscで原文の打鍵履歴と表示を復元
  • 同じ入力状態では取り消した候補を再表示しない
  • Enterは表示を確定、未採用提案を自動採用しない
  • Spaceの候補一覧に補正を2番目「補正」で表示
  • 候補選択開始後は背景結果で並びを変えない

自動反映の制限

  • 完全な辞書語へ一意復元できる隣接キー誤入力のみ
  • または明示採用して確定した記録が3回以上
  • 末尾が入力途中の子音なら自動反映しない
  • 全体が英字だけの識別子は自動反映しない
  • 曖昧な候補は自動反映しない
  • 自動反映だけで採用回数を増やさない
  • 取消・未確定・確定失敗は学習に数えない
